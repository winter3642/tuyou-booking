## W4D1 — Dockerfile + GitHub Actions（简历"CI/CD"落地）

### ① Dockerfile（放仓库根目录，多阶段构建）

```dockerfile
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests

FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

### ② CI 里跑测试的难点（先想清楚再写 yml）

你的测试在 CI 上跑通需要三个条件，**缺一个就红灯**：

| 依赖 | CI 里怎么给 |
|---|---|
| MySQL（tuyou_test 库） | `services.mysql`，`MYSQL_DATABASE: tuyou_test` 自动建库 |
| MySQL 连接凭据 | 本地测试用 `tuyou/tuyou123`，CI 里该用户不存在 → 把 application-test.yml 改成读环境变量（默认值仍是本地凭据，本地开发零影响） |
| Redis（密码 tuyou123） | `services.redis`，`command: redis-server --requirepass tuyou123`（**密码不配，测试必红**） |

**改动 1：application-test.yml 支持环境变量覆盖**（本地行为不变）：

```yaml
spring:
  datasource:
    url: ${TEST_DB_URL:jdbc:mysql://localhost:3306/tuyou_test?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=UTF-8}
    username: ${TEST_DB_USER:tuyou}
    password: ${TEST_DB_PASSWORD:tuyou123}
```

CI 里用 `env: TEST_DB_USER: root, TEST_DB_PASSWORD: root` 覆盖。MySQL 容器用 root 连（`MYSQL_DATABASE` 建的库归 root）。

### ③ `.github/workflows/ci.yml`

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: tuyou_test
        ports: ['3306:3306']
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1" --health-interval=10s
          --health-timeout=5s --health-retries=10
      redis:
        image: redis:7
        ports: ['6379:6379']
        options: >-
          --health-cmd="redis-cli -a tuyou123 ping" --health-interval=10s
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17', cache: maven }
      - run: mvn -B test jacoco:report
        env:
          TEST_DB_USER: root
          TEST_DB_PASSWORD: root
  docker:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with: { push: true, tags: ghcr.io/winter3642/tuyou-booking:latest }
```

> 排错顺序（你踩过的坑套路）：CI 红 → 先本地 `mvn test` 确认能过（差异点只有：时区、密码、环境变量）；再看 Actions 日志里哪个 service 没 ready（health-check 没过就加大 retries）；Redis 密码没配时测试报 `RedisConnectionFailureException`。

**W4D1 验收**：✅ push main 后 Actions 全绿 ✅ GHCR 出现 `ghcr.io/winter3642/tuyou-booking:latest` ✅ README 放 Actions badge（`https://github.com/winter3642/tuyou-booking/actions/workflows/ci.yml/badge.svg`）

## W4D2 — 部署（先本机 Docker 全流程，有服务器再迁移）

### ① `docker-compose.yml`（仓库根目录，本机跑通即简历可写）

```yaml
services:
  mysql:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: tuyou
      MYSQL_USER: tuyou          # 镜像自动建用户并授权 tuyou.*
      MYSQL_PASSWORD: tuyou123
    ports: ['3307:3306']          # 本机 3306 被原生 MySQL 占用，映射到 3307
    volumes:
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql   # 首次启动自动建 10 张表
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1"]
      interval: 10s
      retries: 10
  redis:
    image: redis:7
    command: redis-server --requirepass tuyou123
    ports: ['6378:6379']          # 本机 6379 已被 tuyou-redis 容器占用
  app:
    build: .                      # 本机验证用 build；云服务器改成 image: ghcr.io/...
    depends_on:
      mysql: { condition: service_healthy }
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/tuyou?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
      SPRING_DATASOURCE_USERNAME: tuyou
      SPRING_DATASOURCE_PASSWORD: tuyou123
      SPRING_DATA_REDIS_HOST: redis
      SPRING_DATA_REDIS_PASSWORD: tuyou123
    ports: ['8082:8080']          # 本机 8080 被本地实例占用
volumes:
  mysql-data:
```

> 注意两个坑：① 本机端口冲突，compose 里全换了映射端口，**云服务器上没有冲突就改回 3306/6379/8080**；② 造数脚本 `scripts/gen_data.py` 的 host/port 参数要跟着改（连 3307）。
> 云服务器：安全组放行 22/80/8080 → `curl -fsSL https://get.docker.com | sh` → 仓库里拉 compose 文件（`image:` 换成 GHCR 镜像）→ `docker compose up -d` → 手机 4G 访问 `http://服务器IP:8080/api/destinations` 验证。

**W4D2 验收**：✅ 本机 compose 起三容器，8082 接口通 ✅ 手机流量（如有服务器）可访问 ✅ 重启后 `docker compose up -d` 能恢复

## W4D3 — JMeter 压测（简历核心数字）

### ① 安装

官网下 5.6.x zip → 解压 → `bin/jmeter.bat` 启动（你已有 Java 17）。

### ② 场景一：下单接口压测

下单接口的前置是**购物车条目**（`POST /api/orders` 吃 `cartIds`，下单后购物车被清空），所以每轮循环是「加购 → 下单」两步：

1. 用 Python 造 **200 个测试用户**：注册 → 登录拿 token → 存 `users.csv`（`username,token`）
2. JMeter 线程组：**200 线程、Ramp-up 20s、循环 50 次**
3. CSV Data Set Config 参数化 `token`（每个线程绑定一个用户）
4. 每个循环内：
   - `POST /api/cart`（Header: `Authorization: Bearer ${token}`；Body: `{"skuId":固定SKU,"quantity":1}`）
   - JSON 提取器取返回的 `id` → `POST /api/orders`（Body: `{"cartIds":[${cartId}]}`）
5. 聚合报告记录：**QPS、平均/99% 响应时间、错误率**（截图存档）

### ③ 场景二：超卖验证（必做，简历"超卖率 0"的证据）

1. 准备：`UPDATE t_product_sku SET stock=100 WHERE id=某SKU;`，并 `redis-cli -a tuyou123 DEL stock:sku:某SKU`（**不清 Redis 就测的是旧库存，必踩坑**）
2. 用 Python 造 **1000 个用户**（同上）各 1 条购物车，CSV 存 `user_token,cartId`
3. 线程组 **1000 并发**各下单 1 次
4. 断言（写进报告）：✅ 成功下单数 = 100 ✅ DB 库存终值 = 0 ✅ 无负库存 ✅ 失败请求全部返回"库存不足"（400）

### ④ 优化迭代（记录过程，都是素材）

压完看瓶颈：如 Lettuce 连接池（`spring.data.redis.lettuce.pool.max-active` 调大）、Tomcat 线程数（`server.tomcat.threads.max`）→ 重新压测 → 记录提升幅度。**压测前后的数据都进报告。**

**W4D3 验收**：✅ 聚合报告截图 ✅ 超卖验证通过 ✅ `docs/压测报告.md` 入仓库
